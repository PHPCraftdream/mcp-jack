Delivered behavior worth preserving:

- Request proof/header time may be fixed for rotation; response freshness uses a new clock sample.
- Go SSE refusal cancels the upstream request context and fails writes at header commitment, without detached production goroutines. It remains cooperative: an arbitrary handler ignoring cancellation/write errors cannot be forcibly stopped. Final late SSE headers still yield signed 501.
- Upstream response cap is separate from request cap, default 1 MiB; overflow yields signed 502 response_too_large with upstream bytes/headers discarded. TS ignores empty chunks. Byte caps are not whole-operation deadlines; TS cancellation can itself wait forever on a noncooperative source.
- HTTPS required outside literal canonical 127.x.y.z or [::1]; no hostname/DNS loopback exception. Shared manually maintained URL table has 207 cases and explicit parser differences. Percent escapes are refused in authority only, not ordinary encoded path/query.
- Redirect no-follow set is 301/302/303/307/308. 304 is not a redirect and must retain normal signature verification. TS response-URL comparison ignores fragments but not actual destination changes.
- Go Config.HTTP is copied and always secured. Direct SDK transport chains collapse to one wrapper, Config signer/aud/server key are authoritative, tuning inherits in documented order, cyclic/typed-nil/deep chains are refused, caller objects are not mutated, and redirects are disabled even for permissive caller callbacks.
- Go CallTool uses the existing verified structuredContent convenience contract. It is not a full MCP session client, and content-only tool results are not decoded by that helper. Existing Go null structuredContent behavior was intentionally not refactored.
