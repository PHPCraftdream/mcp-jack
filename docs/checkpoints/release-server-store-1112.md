## TypeScript concrete server ring store — pending CI

Go reference: `durable/server_store.go`, `durable/server_operations.go`. The Go store is a bbolt key-value database with a durable publication intent; the TypeScript/Rust stores already use a single private file with atomic temp-fsync-rename replacement, so a publication is one atomic replace of the whole bundle (old or new state, never a mixture) and uncertain outcomes are handled by the existing dirty/fence/marker gates instead of an intent row. The server store is therefore a thin variation of the accepted client store.

`rotation-store-format.ts` gains a domain-parameterised `packBundle`/`unpackBundle` pair (the client `pack`/`unpack` delegate to it, behaviour unchanged). New `rotation-server-store-format.ts` (anchor server snapshot with one opaque signer reference, profile hash, server-domain pack/unpack that also checks the copied snapshot clock against the guard) and `rotation-server-store.ts` (`RotationServerStore`: `initializeUnused`, `open`, `rawClock`, `snapshot`, `advanceAndCheck`, `checkSnapshotClock`, `compareAndSwap`, `acquireServingLease`, `fence`, `close`). Domain `mcp-jack/server-ring/private-file/v1` keeps client and server files non-interchangeable. `compareAndSwap` requires the captured clock tuple to equal the desired snapshot's clock and the stored guard, validates one fixed-P publication with the existing pure validator, never rewrites the guard, and fences with `rotation_state_unknown` on an uncertain write. Serving leases hold the dirty epoch; `close()` is synchronous, so it refuses new operations immediately and throws `rotation_state_unavailable` (without fencing) until every lease is released, then completes on the next call. Unlike Go, there is no blocking wait.

New `ts/test/rotation-server-store.test.ts` (Linux-gated like the client store tests): dirty-before-clock and marker ordering, exclusive owner, two real fixed-P publications from the independent overlapping fixture chain, stale/duplicate CAS, guard bytes unchanged by CAS, clean reopen; publication refusals (batched, replaced reference, fenced target, moved P, foreign clock tuple, no-op) leaving the file byte-identical; rollback/invalid-time latch that never samples again and blocks clean close; throwing/reentrant/fencing clock callbacks; lease drain semantics; client/server/profile/anchor non-interchangeability. Real crash children are not duplicated because the file owner layer is shared and already covered. No signer selection, response authorization, publication provider or HTTP wiring yet. Acceptance pending actual CI; any failure is repaired in the same cycle.
