## Hickory API port and transport guarantees

The 0.26 migration moves the runtime `Spawn` and `RuntimeProvider` APIs from proto to net. In 0.26.1, the background spawn future's output is unit; resolver construction takes a provider directly, and `build()` returns `Result<Resolver<OwnedRuntime>, NetError>` for this provider. The current implementation maps builder and lookup errors, and separately observes HTTP-driver errors. It does not invent a DNS task error channel: a successful join of the wrapped unit-output DNS future does not prove that a DNS exchange succeeded.

| API surface | Current call/contract and source |
|---|---|
| Runtime spawn/provider | `hickory_resolver::net::runtime::Spawn::spawn_bg` accepts a `Send + 'static` future with `Output = ()`; `RuntimeProvider` supplies the runtime handle and IO types. The implementation owns spawns in its `TaskHandle` and delegates IO to `TokioRuntimeProvider`. [hickory-net 0.26.1 runtime source](https://docs.rs/hickory-net/0.26.1/src/hickory_net/runtime.rs.html) |
| Resolver builder | `Resolver::builder_with_config(dns.config, provider)` receives the provider directly; `.build()` is fallible and maps to a `TransportError`. The resulting type is `Resolver<OwnedRuntime>`. [hickory-resolver 0.26.1 resolver source](https://docs.rs/hickory-resolver/0.26.1/src/hickory_resolver/resolver.rs.html) |
| Test nameserver | `NameServerConfig::udp(peer.ip())` initializes a UDP server entry; the test sets `connections[0].port = peer.port()` to direct DNS to its custom UDP socket. [hickory-resolver 0.26.1 config source](https://docs.rs/hickory-resolver/0.26.1/src/hickory_resolver/config.rs.html) |
| Test DNS message | `Message::new(request.metadata.id, MessageType::Response, OpCode::Query)` carries the request ID; public `queries` and `metadata` are read/set by the test, including recursion flags. [hickory-proto 0.26.1 message source](https://docs.rs/hickory-proto/0.26.1/src/hickory_proto/op/message.rs.html) |

The HTTP transport retains its owned-task lifecycle, absolute 15-second default round-trip deadline, 64-task cap, abort-and-join cleanup, and explicit operation/cleanup error handling. System DNS configuration, hosts, and roots are snapshotted at builder time. There is no detached default Tokio handle, blocking DNS fallback, new unsafe code, crypto-provider change, proxy, retry, connection pool, or public API redesign. TLS continues using rustls with the ring provider and certificate/hostname verification. Cleanup is explicit; it is not delegated to asynchronous `Drop`.

`run_owned` completes the operation, then `drain` closes spawn control, records results from completed tasks, aborts every still-running child, and joins every registered task while collecting its result. Only after `drain` completes does `finish_operation` resolve operation versus cleanup. If cleanup alone fails after a successful operation, that failure is returned. If both fail, a primary `Transport` or `Client` error retains its class and gains the cleanup diagnostic. For primary `Streaming`, `Unauthenticated`, or `Protocol` errors, the exact variant and payload are preserved; because the unchanged `TransportError` enum has no secondary-diagnostic channel, the cleanup diagnostic cannot also be returned and is not logged or stored elsewhere. There is no public API, logging, or dependency change. These are source and test-oracle descriptions, not runtime verification.
